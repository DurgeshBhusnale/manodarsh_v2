🔧 TECHNICAL CHANGES
───────────────────────────────────────────────────────────────────────

BEFORE (Old Code):
  cap = cv2.VideoCapture(1)           # No backend specified
  time.sleep(0.1)                     # Insufficient delay
  ret, frame = cap.read()             # Single frame test
  if ret and frame is not None:
      return cap                       # Accept immediately

AFTER (New Code):
  cap = cv2.VideoCapture(1, cv2.CAP_DSHOW)  # DirectShow backend
  time.sleep(1.0)                            # Proper USB delay
  
  # Discard first 2 frames (warmup)
  for warmup in range(2):
      cap.read()
      time.sleep(0.15)
  
  # Validate with multiple reads
  successful_reads = 0
  for attempt in range(5):
      ret, frame = cap.read()
      if ret and frame is not None and frame.size > 0:
          successful_reads += 1
          if successful_reads >= 3:
              return cap  # Validated!

───────────────────────────────────────────────────────────────────────
🎯 KEY IMPROVEMENTS
───────────────────────────────────────────────────────────────────────

1. DirectShow Backend (cv2.CAP_DSHOW)
   Why: Windows standard for USB camera reliability
   Impact: External USB webcams now properly detected

2. Increased Initialization Delays
   External USB: 1.0 second (was 0.1s)
   Built-in cam: 0.5 second (was 0.1s)
   Why: USB cameras need more time on Windows

3. Frame Warmup Period
   Discards first 2 frames after opening
   Why: USB cameras often produce black/corrupted initial frames

4. Multi-Frame Validation
   Requires 3 successful reads out of 5 attempts
   Why: Single frame test insufficient for USB devices

5. Enhanced Logging
   Every step logged with [CAMERA] prefix
   Why: Easy troubleshooting and diagnostics

6. Camera Enumeration
   New method to list all available cameras
   Why: Diagnostic capability for IT support

7. Diagnostic API Endpoints
   GET  /api/image/diagnostics/camera-test
   POST /api/image/diagnostics/camera-cleanup
   Why: Remote diagnostics and troubleshooting

⚠️ TROUBLESHOOTING
───────────────────────────────────────────────────────────────────────

IF CAMERA STILL NOT DETECTED:

1. Check Windows Device Manager
   → Cameras (or Imaging devices)
   → Look for yellow warning icon
   → Update driver if needed

2. Check Windows Privacy Settings
   → Settings → Privacy & Security → Camera
   → Ensure "Let apps access your camera" is ON
   → Ensure "Let desktop apps access your camera" is ON

3. Try Different USB Port
   → Use USB 2.0 port (not 3.0)
   → Try port directly on PC (not hub)

4. Check Camera in Other Apps
   → Open Windows Camera app
   → Verify camera works there
   → Close before testing CRPF system

5. Check Backend Logs
   → backend/cctv_monitoring.log
   → Look for [CAMERA] entries
   → Error messages will indicate specific issue

6. Use Diagnostic API
   → GET /api/image/diagnostics/camera-test
   → Shows all available cameras
   → Indicates specific failures
